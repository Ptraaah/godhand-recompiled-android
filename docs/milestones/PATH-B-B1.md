# Path B, stage B1 — PCSX2 GS connected through the bridge (Vulkan, surfaceless)

Status: **built and packaged; the device verdict is the owner's run** (install,
default-boot check, flip the switch, title screen). Nothing about the default
renderer changed: with the switch untouched, 0.25 is 0.24 plus an unused
library in the APK.

## What was built

### 1. The bridge: `libpcsx2gs.so` (path-b, new target `pcsx2gs`)

`path-b/compat/BridgeVK.cpp` — the DX11 bridge (`thirdparty/pcsx2-gs/compat/
Bridge.cpp`, same GS, same upstream commit) with the platform parts replaced,
per the spike's delta list:

- `WindowInfo::Type::Surfaceless`, no window handle; `GSopen(options,
  GSRendererType::VK, ...)` instead of DX11. No swap chain is ever created.
- Present harvest: new separate export **`pcsx2gs_grab_frame(dst, capacity,
  &w, &h) -> bytes`** (the API table and `PCSX2GS_API_VERSION` are untouched,
  same pattern as `pcsx2gs_set_aspect`). It snapshots the composed frame via
  `GSSaveSnapshotToMemory` — which works surfaceless because
  `GSRenderer::VSync` merges DISPFB into the device's current texture whether
  or not a swap chain exists, and `GSDeviceVK::BeginPresent` skips the actual
  present without one. The bridge caches the snapshot and only re-downloads
  when its vsync counter changed, so repeated grabs inside one host frame are
  cheap. Pixels are tightly packed RGBA8, row 0 = top — exactly what the host
  present path uploads.
- Deleted, not stubbed: the DXGI present-statistics writer, the BMP snapshot
  writer (`Snapshot` now reports failure; the grab replaces it), and
  `ApplyGameFixes` (that was Urban Reign's GameIndex entry; God Hand needs no
  GSC hacks — configuration only). The options parser (`key=value;...`) is
  carried over unchanged.
- After a successful open the bridge logs the negotiated feature paths (see
  below) as one `[pcsx2-gs] VK features:` line.
- `path-b/compat/BridgeLinkStubs.cpp` — the link closure the B1-prep vktest
  proved: two real upstream helpers (`GSOptions::TriStateToOptionalBoolean`,
  `Host::ReportFormattedErrorAsync`) plus inert placeholders for the excluded
  software renderer. The placeholders' only referencer is the HW renderer's
  `SwPrimRender` path, which is master-gated by
  `GSConfig.UserHacks_CPUSpriteRenderBW` — upstream default `0` = off
  (`pcsx2/Config.h:892`), and the bridge never enables it. They cannot execute
  in path B; the file header says so and says what the real fix would be if
  CPU sprite render is ever wanted.
- Shaders are **baked into the .so** with the fork's own
  `BAKE_SHADERS_IN_CPP` mechanism (generated by upstream's
  `tools/shader_to_cpp.py` from `src/bin/resources/shaders/{vulkan,common}`,
  wired in `path-b/CMakeLists.txt`): `libpcsx2gs.so` needs no resources
  folder on the device. The `opengl_*` arrays `GSDevice.cpp` also includes
  are generated empty — no GL renderer is compiled and no code path reads
  them (VK device only).

Result: `path-b/build-b1/libpcsx2gs.so`, **28,041,184 bytes**, linked with
`-Wl,--no-undefined` (the B0 closure discipline — a missing symbol fails the
build, not the device run). Exports verified: `pcsx2gs_get_api`,
`pcsx2gs_set_aspect`, `pcsx2gs_grab_frame`. `DT_NEEDED` is only
libdl/liblog/libm/libc — Vulkan and `libshaderc_shared.so` are dlopened at
run time by the GS itself, as in B0.

### 2. The Android backend variant (`gs_pcsx2_backend.{h,cpp}`)

The Windows code is preserved; the platform split is `#if` by `#if`:

- The real implementation now compiles when
  `(_WIN32 || __ANDROID__) && __has_include("pcsx2gs_api.h")`. The game
  CMake adds the header's include dir to `ps2_runtime` for Android only
  (`godhand-recomp/CMakeLists.txt`), so the desktop build still compiles the
  inert stub branch exactly as before.
- `Requested()`: the env parse is shared (`PS2X_GS_RENDERER` must equal
  `pcsx2`, case-insensitive). The Android arm `dlopen("libpcsx2gs.so",
  RTLD_NOW | RTLD_LOCAL)` (the soname resolves from the app's native lib
  dir), resolves `pcsx2gs_get_api` (version-checked), `pcsx2gs_set_aspect`
  (optional) and `pcsx2gs_grab_frame` (**required** — surfaceless there is no
  other present path, so a library without it falls back to the built-in GS
  instead of black-screening). Success logs
  `[gs] renderer: PCSX2 GS (libpcsx2gs.so, Vulkan)`; every failure logs its
  reason and returns false, so `GSThreadedBackend::MakeDefault` (unchanged)
  keeps the built-in backend.
- `Active()` is **false on Android, deliberately**: the host loop reads it
  as "the DLL presents itself" and would stop uploading frames. Frames come
  back through `Present()` instead. `AttachHostWindow`/`HostTick` are
  no-ops (no child window); the nominal client size 640×448 is recorded so
  the vsync resize check stays stable.
- `Present()` (was an inline `return {}` in the header; now a declaration
  with per-platform definitions): Windows returns {} as before; Android
  harvests via `pcsx2gs_grab_frame` (size query, then copy) into a
  `PresentationFrame`. The threaded backend and ARUS pillars 3/4 sit above
  this, untouched.
- `EnsureOpen()` Android arm: no child-window requirement; `hwnd=nullptr`;
  640×448; scale from `PS2X_GS_SCALE` (1–8, default 1); folders under the
  process cwd (the glue chdirs to the app files dir): resources
  `<cwd>/pcsx2-resources` (created; only has to exist — shaders are baked),
  Vulkan shader cache `<cwd>/shadercache_pcsx2`. Vsync default is
  `Disabled` on Android (`PS2X_PCSX2_VSYNC` overrides): the host loop paces
  presents, and a FIFO/mailbox mode would let the GS skip fields.

## Feature negotiation vs the POCO F5 census

Checked against `GSDeviceVK` at the pinned commit
(2954ebe6965669219f1bbd256e958fbd8f83a85d) and the B1-prep device census
(Vulkan 1.3.0 instance / 1.1.128 device, 90 extensions):

- **Only one hard requirement exists**: `VK_KHR_push_descriptor`
  (`s_required_device_extensions`, GSDeviceVK.cpp:143) — present in the
  census. Nothing in this snapshot's renderer uses dynamic rendering.
  Surfaceless also drops the swapchain-extension requirement
  (`SelectDeviceExtensions(enable_surface = surface != VK_NULL_HANDLE)`).
- Expected picks on this driver (the bridge's `[pcsx2-gs] VK features:` line
  in the owner boot log confirms them on the real run):
  - `framebuffer_fetch=0` — needs `VK_EXT_rasterization_order_attachment_
    access`, absent. The render-pass path is used instead.
  - `texture_barrier=1` → `feedback_loops=1` — upstream defaults
    `OverrideTextureBarriers` to −1 ("auto") and the snapshot's
    `CheckFeatures` sets `texture_barrier` when the setting is `!= 0`, so
    the barrier path is taken even without the feedback-loop extensions.
    Destination-alpha/blend work goes through texture barriers.
  - `rov=0` — no `VK_EXT_fragment_shader_interlock` in the census.
  - `provoking_vertex=1` — `VK_EXT_provoking_vertex` is present.
  - `stencil=?` — set only if D32S8 supports optimal-tiling depth-stencil
    attachment on the device; `CheckFeatures` decides at open. This is the
    one pick that is a device-run question, not a code question.
- `CheckFeatures` hard-fails only on per-format feature bits (RGBA8,
  A2B10G10R10, R16G16B16A16F, D32S8, R32F, integer formats: sampled +
  color-attachment bits). If any were missing, open fails with
  "Required format %u is missing bits" in the log — that would be the
  stop-and-report case. The Adreno 725 exposes all of these in its format
  table per the census data we have; the owner log is the confirmation.

## The switch

`godhand.ini` in the app files dir
(`/storage/emulated/0/Android/data/dev.ptraaa.godhand/files/godhand.ini`),
section `[video]`:

```
Renderer=pcsx2
```

Default ships `Renderer=native` (unchanged). The settings loader maps it to
`PS2X_GS_RENDERER`; setting that env var directly also works and wins over
the ini. Same escape-hatch shape as the ARUS pillar switches: set it back to
`native` and the build is 0.24 again, no reinstall needed.

The boot log states the active backend either way: the settings lines print
`PS2X_GS_RENDERER=<value>` at startup, and a successful PCSX2 activation
adds `[gs] renderer: PCSX2 GS (libpcsx2gs.so, Vulkan)` plus the bridge's
`[pcsx2-gs] Vulkan surfaceless, ...` and `[pcsx2-gs] VK features: ...`
lines.

## Verification done here

- path-b B1 build: exit 0; `libpcsx2gs.so` linked under `--no-undefined`;
  exports and `DT_NEEDED` inspected (above).
- Android game build (`build/android-m2a`, target `godhand`): exit 0.
  Compile flags for the touched TU are byte-identical to the pre-B1 build;
  its include line gained exactly one entry (the API header dir).
  Note: the run rebuilt the whole tree (~12.6k edges) and a service restart
  interrupted it once; the resume finished clean. The same wholesale rebuild
  triggers in the desktop tree after the CMakeLists touch (observed, cause
  not fully pinned down — the desktop tree's `.ninja_log` is absent, which
  alone forces one); outputs are deterministic — flags verified unchanged.
- Desktop configuration: `gs_pcsx2_backend.cpp` (stub branch) and
  `gs_threaded_backend.cpp` (header consumer) compiled with the desktop
  tree's own recorded compile commands — both exit 0. A full desktop relink
  + boot smoke was not run: the desktop tree faces the same wholesale
  rebuild (its `.ninja_log` is absent) and the stub branch's runtime
  behavior is unchanged by construction (`Requested()` false →
  `MakeDefault` picks the built-in backend exactly as before; `Present()`
  returns {} as the old inline did). The on-device default-boot step below
  is the end-to-end proof on the shipping artifact itself.
- Host-side code audit of the present path: `GSDeviceVK::BeginPresent`
  returns `FrameSkipped` without a swap chain after executing the command
  buffer; `GSRenderer::VSync` still merges into `m_current`;
  `GSSaveSnapshotToMemory` stretches/downloads `GetCurrent()` — no
  swapchain is touched anywhere on the harvest path.

Known B1-acceptable cost, flagged for B2: the harvest does a synchronous
snapshot download per presented frame (the spike's failure mode 2). If the
title screen renders but slowly, pipelining this download is B2's first
job, ahead of any renderer tuning.

## Owner test steps (the B1 verdict)

1. Install `godhand-0.25-m24-pathb.apk` over the current build (same
   signer, in-place update).
2. **Boot once without changing anything.** It must behave exactly like
   0.24 (this proves the default renderer is untouched). Then close it.
3. Open `godhand.ini` in the app files dir (see "The switch" above) and
   change the `[video]` line to `Renderer=pcsx2`. Save.
4. Boot the game and let it reach the **title screen**.
5. Send back:
   - a screenshot of the title screen (or of whatever appears instead —
     black screen, freeze, or crash are all verdicts), and
   - the full boot log from that run. It must contain
     `[gs] renderer: PCSX2 GS (libpcsx2gs.so, Vulkan)`,
     `[pcsx2-gs] Vulkan surfaceless, ...`, and
     `[pcsx2-gs] VK features: ...`. If instead it shows
     `[pcsx2-gs] GSopen failed` or "Required format ... is missing bits",
     send the log as-is — that is the precise failure B1 needs to know.
6. To switch back at any point: `Renderer=native` in the same file. No
   reinstall needed.
