# Path B — pipeline test build (0.28-m27-pipeline, versionCode 35)

**What this is.** A single-variable packaging of the approved
bridge-pipeline stage (PATH-BRIDGE-PIPELINE.md) on top of the b5-revival
build (0.27-m26-b5revival, PATH-B5REVIVAL.md). Exactly one payload file
differs from the revival: the bridge `lib/arm64-v8a/libpcsx2gs.so` is the
pipelined build from `path-b/build-b1/libpcsx2gs.so` (the approved
pipeline patch to `path-b/compat/BridgeVK.cpp`). Everything else is the
revival's bytes, which are b5's bytes. Method is the revival's: binary
repackage, no payload compilation — manifest version fields patched in
the binary AXML (string-pool rebuild + in-place int patch; `aapt2 dump
xmltree` diff of base vs new manifest shows the two version attributes
and nothing else), payload entries stored, manifest deflated, external
entry set and order identical to the base, `zipalign -p 4`, signed with
the project pipeline's build-tools 36.0.0 and the shared debug keystore
(`recomp-android/probe/debug.jks`). The hashes below were computed from
the *final signed* APK, extracted and compared file by file against the
extracted base APK.

## The lines that arbitrate the device run (from PATH-BRIDGE-PIPELINE.md)

No performance outcome is claimed here; the device boot log decides.
Same protocol shape as before (cool phone, the pathb5 route, wide off):

- **Boot proof of correct packaging:** `[pcsx2-gs] pipeline on: the GS
  runs on the bridge thread, depth 2 fields ...` — its absence convicts
  the packaging (wrong .so) or the env (`PS2X_GS_PIPELINE=0` seeded
  from the ini).
- **`[pathb] pipeline:`** lines (every ~300 executed fields):
  `ahead_max` must never exceed the depth; `park` is the pipeline's own
  producer park and should read as a small fraction of the old drain
  totals.
- **`[ee-work]` `parked: sync ... present ...`** per fight window,
  against b8's ≈416 + ≈319 ms (light) and up-to-719 ms sync (fights):
  the conviction metric. If these do not fall, the pipeline is not
  landing, whatever fields/s does.
- **`[frame-split]` `sync` ms/% and `fields +N`** per window: the felt
  number; fight fields/s against the 44–52 pathb5 floor and b8's
  31.7–47.
- **`[pathb] harvest: ... readback_wait=...`**: must stay in its
  historical range (b8: 50–105 ms per 5 s window); a jump indicts the
  capture mutex, not the queue.
- **Kill switch / A/B attribution:** `PS2X_GS_PIPELINE=0` in the
  external `godhand.ini` makes every entry point run its Direct twin —
  the reconstructed b5 behaviour in the same binary — so one build
  separates the pipeline from the reconstruction with no second
  install. `PS2X_GS_PIPELINE_DEPTH=n` sets the field bound (1–8,
  default 2).
- The revival report's owner-ini caveat applies unchanged: an external
  `godhand.ini` renderer line overrides the variant seed, so the ini
  must be in the known pathb5-route state for a clean verdict.
